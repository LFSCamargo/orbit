# Game artwork and import enrichment

In **Edit game**, each artwork slot supports a local file, **Browse images**, **Random SteamGridDB**, and clearing. Browsing queries configured SteamGridDB, TheGamesDB, RAWG, Wikimedia Commons, and Steam Store (for known Steam IDs). The picker provides a source filter and downloads the chosen image before applying it to the draft. Save persists the draft; cancel leaves the saved game unchanged. Randomization uses the matching SteamGridDB game, avoids the previous result when alternatives exist, and tries another candidate if a download fails.

SteamGridDB requires its API key in Settings or the backend environment. TheGamesDB and RAWG require their own keys; their absence does not block other providers. Wikimedia and known Steam Store artwork do not require keys. Search results may include similarly named games for manual selection. Automatic enrichment and randomization use conservative title matching or a known Steam identity. Numeric emulator IDs are never treated as Steam IDs.

When automatic metadata enrichment is enabled, new imports and rescanned games with incomplete artwork are enriched independently through the configured providers. Canonical titles are accepted only for confident matches. Existing custom artwork is preserved. Download failures leave other slots eligible for enrichment. Every touched imported game receives usable cover, hero, and icon references: existing artwork is reused where needed, and a generated local image is the offline fallback. Generated images remain eligible for enrichment on a future scan. This guarantees a visual fallback, not an authentic game cover when providers are unavailable. Disabling automatic enrichment still supplies local fallbacks.

Provider credentials remain in the Rust backend. Browser development uses labeled sample results; it does not contact providers or test real credentials. Live-provider requests and native window controls need verification in the Tauri app with configured keys.
